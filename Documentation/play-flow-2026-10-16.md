# Play and matchmaking flow

The hub after Start has three large cards: Play, Gacha and Inventory. Profile,
Settings, Shop, music and logout stay available as smaller controls.

Play opens four expanding categories. PVE has Bot Rush; Chaos and Classic each
have Normal and a disabled Ranked row labelled Coming soon. Selecting a category
does not select a row. A checked available row enables the Play button. Checks
use vector geometry so their visibility does not depend on the UI font.

CUSTOM has Create room and Browser room. Both pass through the shared loadout;
Continue opens the existing creation/settings or room browser UI. Custom rooms
can use Classic or Chaos. The browser retains code entry, pagination and room
joining, and now includes the same ruleset filter. Back returns to the loadout,
then Play selection. Leaving a custom match preserves its lobby destination.

Every lobby shows its selected category/submode above the loadout. PVE proceeds
from Find Match to the bot roster and then to the new White/Black cards. A single
player chess set selected before choosing a color follows that color; board and
move-effect choices are retained.

Online Normal lobbies retain their loadout while queueing and accepting a match.
Find Match becomes an elapsed timer with X and cancels on one click. Cosmetics
and navigation are locked while a queue/match reservation exists. A found match
opens an Are you sure?? modal with Yes/No and the existing server countdown.
Accepting twice is disabled, and No uses the existing decline/leave endpoint.
Cancelling or declining returns to the same loadout. Explicit lobby reopening or
authentication lifecycle changes rebuild the collection for the current session.

Chaos is the displayed name. The existing server ruleset key Aram, JSON fields,
buff identifiers and networking endpoints are preserved. Ranked is unavailable.

The camera-lock hint stays 12 reference UI units from the safe lower-left corner;
bot companion and journal reserved space do not lift this hint.

All match entry paths (PVE, local two-player, Chaos practice, online Normal and
custom rooms) use LoadingManager and LoadingUI. Local restart now also uses that
same boundary and retains the match's exact loadout. Addressables dependencies
finish before instantiation. With the opaque loading canvas still present, the
actual match renders over several frames and selected streamed textures wait
for the camera's requested mip levels. Temporary mip requests are cleared after
preparation; a timeout uses the existing Retry / Back error screen. Gameplay
input, bot turns, online commands and Ready acknowledgements stay blocked until
loading finishes. Local elapsed time starts after loading; online clocks remain
server-owned. No new artwork, duplicate match scenes or global shader warmup is
introduced.

## Validation

`PlayFlowAudit.Run` passed 72 local fixture checks: hub actions, mode/row selection,
visible vector checks, custom creation/browser controls, camera hint placement,
Ranked locks, mode headers, queue cancellation, confirmation states, lobby/session
lifetimes, PVE color transfer and control bounds at 1920x1080, 1280x720, 800x600
and 1080x1920. Report: `Logs/play-flow/checks.txt`.

Runtime Editor, runtime Player and Editor-tool C# checks also passed. These checks
do not connect to the game backend, modify account equipment, capture screenshots
or exercise a real two-account match. Live matchmaking, acceptance races, actual
Game View appearance and bot gameplay remain manual verification steps.
The fixture runs with no graphics device, so it does not validate GPU material
preparation, texture streaming or rendering in a real match.
